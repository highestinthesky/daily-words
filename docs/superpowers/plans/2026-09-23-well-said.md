# Well Said Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a polished static site that shows the same five useful words to every visitor each New York day.

**Architecture:** Vite bundles a local word bank and pure date-based selection module. The browser renders the daily set and refreshes it on a date change; GitHub Actions publishes the static build.

**Tech Stack:** Vanilla JavaScript, Vite, Anime.js, Vitest, CSS, GitHub Pages.

**Spec:** `docs/superpowers/specs/2026-09-23-well-said-design.md`

## Global Constraints

- `America/New_York` determines the date for all visitors.
- Exactly five distinct words appear; after the first seven days, one is a review from two to six days earlier.
- No accounts, streaks, check-ins, content API, or scheduled daily deployment.
- The build uses relative asset URLs for GitHub Pages project paths.
- Motion respects `prefers-reduced-motion`.

## Review Focus

- A visit just before and after midnight New York time yields different dates and selections.
- Daylight-saving changes do not skip or repeat an editorial date.
- Review words actually appeared as new words two to six days earlier.
- The five visible words are distinct on every tested date.
- Narrow screens and reduced motion preserve readable content.

**Files:** Create `src/words.js`, `src/daily.js`, `tests/daily.test.js`.

**Interfaces:** `getEditorialDate(instant)` returns `YYYY-MM-DD`; `getDailyEdition(dateKey, bank)` returns `{ dateKey, words: [{ ...entry, isReview }] }`; `getNewWords(dayIndex, bank)` returns four or five entries.
